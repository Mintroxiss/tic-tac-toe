# Веб-приложение "Крестики-нолики"

## Описание проекта

Веб-приложение **«Крестики-нолики»**, реализованное на языке **Java** с использованием фреймворка **Spring**.
Проект демонстрирует основы построения веб-приложений, работу со слоями архитектуры, алгоритм **Минимакс** и многопользовательский режим в реальном времени.

## Стек технологий

- **Java 21**
- **Spring Boot 3.5** (Web, Security, Data JPA, Thymeleaf, Scheduling)
- **PostgreSQL** — хранение игр и пользователей
- **Gradle** — сборка (multi-module)
- **Docker / Docker Compose** — запуск базы данных и API

---

## Модули

Проект разделён на два независимых Spring Boot приложения:

| Модуль | Порт | Описание |
|--------|------|----------|
| `api`  | 8080 | REST API — игровая логика, авторизация, хранение |
| `ui`   | 8081 | Веб-интерфейс — Thymeleaf + сессионная авторизация |

---

## Запуск

### Требования

- Java 21+
- Docker

### 1. Собрать API

```bash
./gradlew :api:bootJar
```

### 2. Запустить PostgreSQL и API через Docker Compose

```bash
docker compose up -d
```

### 3. Запустить UI

```bash
./gradlew :ui:bootRun
```

Открыть в браузере: [http://localhost:8081](http://localhost:8081)

## Архитектура API

Приложение построено с чётким разделением на слои:

- **web** — REST-контроллеры, DTO, маппинг
- **domain** — бизнес-логика игры, сервисы
- **datasource** — JPA-сущности, репозитории, маппинг
- **di** — конфигурация Spring Security

---

## Domain layer

- Игровое поле — матрица `CellType[][]` (EMPTY / X / O)
- Модель `Game` содержит: `UUID`, поле, ID игроков, состояние, чей ход, победитель
- `GameState`: `WAITING` → `PLAYER_TURN` → `DRAW` / `PLAYER_WIN`
- Сервис реализует:
    - алгоритм **Минимакс** для хода компьютера
    - логику смены ходов в двухпользовательской игре
    - автоудаление ожидающих игр по таймауту (30 минут)

---

## Datasource layer

- **PostgreSQL** через Spring Data JPA
- `GameEntity` — хранит игровое поле в виде JSON-строки
- `UserEntity` — логин и хэш пароля
- Mapper'ы для преобразования между слоями

---

## Web layer (API)

REST-эндпоинты:

| Метод | URL | Описание |
|-------|-----|----------|
| `POST` | `/api/auth/signup` | Регистрация |
| `POST` | `/api/auth/login` | Вход, возвращает `userId` |
| `POST` | `/api/game/new` | Создать игру (`vsComputer: true/false`) |
| `GET`  | `/api/game/available` | Список игр в ожидании |
| `POST` | `/api/game/{id}/join` | Присоединиться к игре |
| `POST` | `/api/game/{id}/move` | Сделать ход |
| `GET`  | `/api/game/{id}` | Получить состояние игры |
| `DELETE` | `/api/game/waiting` | Отменить свои ожидающие игры |

Авторизация — HTTP Basic Auth. Игровые эндпоинты доступны без авторизации (для анонимной игры).

---

## Режимы игры

- **Игра с компьютером** — компьютер всегда ходит оптимально (Минимакс)
- **Игра двух игроков** — один создаёт игру, второй присоединяется; ходы чередуются, страница обновляется через поллинг каждые 2 секунды
